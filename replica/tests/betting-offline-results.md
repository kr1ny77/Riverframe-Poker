## Как подтверждена работа без сети

Отключён **IP-доступ процесса тестируемого приложения**. Host-инструмент `Tools/prepare-offline-profile.py` компилирует системный sandbox policy: `allow default` и запрет inbound/outbound IP. Debug Simulator-only инструментация применяет эти байты к процессу приложения до игрового UI. Игровые состояния/данные остаются штатными.

Для каждого из **пяти отдельных запусков** приложение реально вызвало TCP `connect` к внешнемуIP1.1.1.1:443 и loopback127.0.0.1:443. Получены `sandbox_result=0` и **EPERM(errno1)** для обеих попыток во всех пяти процессах. [Сводка и PID](evidence/ios-20261017-014552/network-proof/summary.json), [проверка драйвера](evidence/ios-20261017-014552/network-proof.txt), исходные JSON находятся рядом со сводкой.

Отдельный canary в том же Simulator применил этот compiled policy и фактически проверил **IPv4 TCP, IPv4 UDP, IPv6 TCP, IPv6 UDP**: все четыре операции вернули EPERM, процесс завершился с exit0. [Результат canary](evidence/betting-offline-20261017/ipv4-ipv6-tcp-udp.txt), [скомпилированный policy/хеш](evidence/ios-20261017-014552/compiled-network-profile.json). Во время сбора доказательств контрольные TCP-соединения с Mac к1.1.1.1 и example.com:443 успешно установились; хостовая сеть оставалась доступной.

Отдельная проверка `Tools/collect-offline-proof.py` обязательна для офлайн-приёмки: один успешный UI-тест без её доказательств не засчитывается как офлайн. Источником результата являются системный отказ реальных соединений и выполненный UI-путь; анализ исходников и иконка Wi-Fi для этого не использованы.

**Границы метода:** это изоляция IP текущего приложения на данном host kernel/Simulator. Локальный IPC и другие процессы Simulator/macOS продолжают работать. Метод использует закрытый sandbox SPI `__sandbox_ms` и host-совместимый бинарный policy; совместимость с другими версиями macOS/Xcode потребует повторной проверки. QA-код защищён `#if DEBUG && targetEnvironment(simulator)`, включается явным environment; физические устройства и Release исключают эту ветку. Системный авиарежим и радиомодули физического iPhone этим прогоном не проверены.

## Дефект и пределы изменений

BUG-005(S3) воспроизведён до изменения: перед подтверждением all-in отображался диапазон20…1000, точные total/payment отдельно отсутствовали. [Падающий UI-тест](evidence/betting-offline-20261017/confirmed-before.txt) и [снимок до исправления](evidence/betting-offline-20261017/before-screens/ED5C9347-72AA-4EAB-97D8-4EACDB2E5AC3.png) сохранены. BetEditor теперь показывает эти две суммы из существующих legal/snapshot данных; тот же тест и случай предварительного вклада прошли.

Изменения продукта: две подписи all-in в `App/UI/PokerTrainerViews.swift`. QA-инструментация: условный Simulator-only bootstrap в `GameViewModel.swift`, фикстуры через публичные команды существующего движка, новые XCUITest и tools подготовки/проверки сетевого policy. Новых пакетов и продуктовых зависимостей нет.

[Проверка границ изменений](evidence/betting-offline-20261017/scope-preservation.json): исходные SHA-256 Cards.swift/HoldemGame.swift/app entry совпадают с прежними; GameViewModel после удаления добавленной QA-инструментации совпадает с прежним файлом; игровой UI после удаления двух добавленных подписей совпадает с прежним игровым блоком. Правила, политики ботов, режимы и математические модули сохранены.

## Следы настройки стенда и непроверенное

Ранние попытки `sandbox_init` внутри Simulator упирались в отсутствующую runtime-библиотеку; host launcher с exec терял подключение автоматизации. Также исправлены ожидание fold на бесплатном check и сравнение локализованного разделителя тысяч в самом тесте. Два промежуточных QA-прогона пересеклись на одном устройстве и были остановлены. Эти попытки сохранены в `evidence/betting-offline-20261017/`; их результаты исключены из итоговых15 passed. Окончательные доказательства относятся к отдельному чистому QA-устройству и последовательным прогонам.

Проверка ограничена перечисленными состояниями и iPhone17e/iOS27.0 Simulator. Физический iPhone, iOS17, системный авиарежим, полная VoiceOver/Reduce Motion-приёмка, все размеры экранов, длительная игра и все возможные стеки остаются отдельными областями. Исключения ядра и прежние математические тесты подтверждают свои наборы состояний; они не заменяют UI-приёмку каждого возможного состояния.

Для повторения: `./Tools/test-ios.sh` из корня Poker. Он создаёт отдельный QA-симулятор, прогоняет UI, проверяет сетевые JSON, выполняет fault-injection, восстанавливает QA-историю и удаляет свой симулятор. Старые результаты сохраняются в отдельном каталоге с timestamp.
