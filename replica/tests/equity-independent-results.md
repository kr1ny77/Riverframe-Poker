# Независимая проверка equity известной руки

Дата: 17 октября 2026. Область: точность учебной HU-модели NLHE и входных карт. Изменены только тесты и документация.

## Метод и независимость

Production `KnownHandEquityQuestion.calculate()` перебирает неупорядоченные пары и вызывает `HandEvaluator.best` с перебором пятёрок. Новый oracle строит колоду отдельно по мастям и рангам, перечисляет **упорядоченные** тёрн–ривер и сравнивает семикарточные ранги через `independentSevenCardRank`. Этот проверяющий оценщик агрегирует ранги/масти сразу по семи картам; его результат сверяется с production на прежних 5000 seeded семёрках в общем suite. Во время вычисления контрольных W/T/L oracle вызывает только собственный оценщик. Общий тип Card хранит идентификатор физической карты.

Результаты сначала сравниваются с фиксированными числовыми векторами, затем с production. Источник контрольных значений — закреплённые задачи прошлого этапа и аналитические граничные примеры, независимо подтверждённые локальным oracle. Внешний poker calculator или платный solver в проверке не использовался.

Удаление карт подтверждено для каждой задачи: 7 известных → 45 оставшихся на флопе; 8 → 44 на тёрне. На каждом терминальном борде проверена уникальность всех известных и добавленных карт. В ordered oracle каждая из 990 пар встречается ровно дважды (1980 обходов); каждое из 44 продолжений тёрна — один раз. Счётчики делятся на эту кратность после обхода. Целочисленные W/T/L совпали во всех восьми векторах.

| EQ-E1 | A♠ K♠ / A♥ K♥ / T♠ J♠ Q♠ | 990 / 0 / 0 | 1 = 100 % |
| EQ-E2 | Руки EQ-E1 поменяны местами | 0 / 0 / 990 | 0 |
| EQ-E3 | A♠ K♠ / A♥ K♥ / T♠ J♠ Q♠ 2♠ | 44 / 0 / 0 | 1 = 100 % |
| EQ-E4 | Руки EQ-E3 поменяны местами | 0 / 0 / 44 | 0 |
| EQ-E5 | A♠ A♥ / K♠ K♥ / 2♠ 7♥ 9♦ 3♣ | 42 / 0 / 2 | 21/22 ≈ 95,454545… % |
| EQ-E6 | K♠ A♥ / Q♥ A♦ / 2♠ 3♠ 4♠ 5♠ | 42 / 2 / 0 | 43/44 ≈ 97,727272… % |

Аналитическая проверка: в E1/E3 готовый royal flush сохраняет первое место на любом продолжении; E2/E4 — противоположная сторона той же ситуации. В H2 руки совпадают по рангам и флеш невозможен на rainbow-тёрне при одной оставшейся карте, поэтому все исходы делятся. В E5 только два оставшихся короля дают сопернику победу. В E6 A♠ или 6♠ завершают общий стрит-флеш и делят банк; прочие 42 карты сохраняют преимущество флеша K♠. Готовая ведущая рука может терять equity: E5 имеет 2 проигрышных исхода, E6 — 2 разделённых.

Формула проверяется через целые полубанки: equity=(2W+T)/(2N). Например E6 даёт (84+2)/88=43/44. Сравнение Double с рациональным контрольным значением допускает только машинную погрешность 10⁻¹² процентного пункта. Округлённые строки UI рассматриваются отдельно от точных счётчиков.

Машиночитаемые векторы: [equity-reference-vectors.csv](equity-reference-vectors.csv).

## Невозможные карты и регрессия

EQ-N1: все пары позиций известных карт превращены в дубликаты: C(7,2)+C(8,2)=21+28=49 входов. Каждый вход отклонён `EquityLessonError.invalidCards` до расчёта: повторы внутри руки, между игроками, внутри доски и между рукой и доской. В общем suite сохранены проверки неверного размера рук/борда и чтения числовой истории.

Итог: 8/8 числовых векторов и 49/49 отказов для дубликатов. Две новые Swift Testing функции (одна параметризована восемью векторами) прошли; весь release suite — 21/21 функций, без failures. [Фокусный прогон](../verification/equity-independent.txt), [весь suite](../verification/equity-independent-regression.txt). Тестовый helper открыт для повторного использования внутри test target; production-исходники сохранены.

При подготовке дополнительного вектора исходное ожидание одной ничьей у тройки королей было ошибочным: четвёртый король даёт каре только обладателю карманного короля. Оба оценщика показали 44/0/0. Контрольный пример заменён E6 с аналитически проверяемыми двумя общими стрит-флешами. Исправлен тестовый набор; дефект приложения не воспроизведён. Открытых новых дефектов: S1=0, S2=0, S3=0, S4=0.

## Точное, округлённое и непроверенное

- **Точно:** все исходы восьми конкретных задач, W/T/L, отсутствие известных карт в остатке колоды, деление банка, 49 отказов для дубликатов, рациональная доля банка. Монте-Карло здесь отсутствует.
- **Округление:** десятичное отображение процентов в интерфейсе и машинный Double; приёмочный допуск ответа ученика ±0,5 п.п. является педагогическим критерием, а не погрешностью перебора.
- **Модель:** равновероятная неизвестная колода, два открытых игрока, один общий банк, завершённые ставки. Вывод условен относительно этих данных. Числа 0 % и 100 % точны в соответствующих состояниях модели.
- **Отдельная приёмка:** произвольные диапазоны, multiway, side pots, будущие ставки и выбор действий. Исчерпывающий перебор всех допустимых исходных NLHE-состояний не проводился. Новые изменения относятся только к тестам; UI-приёмка и сохранение из [предыдущего этапа](equity-results.md) сохраняются как отдельное историческое доказательство. Новый UI-прогон, физический iPhone и сеть в этом проходе не проверялись.

Повтор: `swift test -c release --filter 'equityMatchesIndependentOracle|equityRejectsEveryDuplicateLocation'`, затем `swift test -c release` из корня Poker.
