# Формат и модель урока equity против диапазона

Версия: 1; дата: 17 октября 2026. NLHE, офлайн, heads-up. Компоненты: `RangeEquityLesson.swift`, `RangeEquityLessonView.swift`.

## Вход и валидация

`RangeEquityQuestion`: `id`, `hero: [Card]` (2), `board: [Card]` (3/4), `range: [WeightedOpponentHand]` (1…8).

`WeightedOpponentHand`: `cards: [Card]` — две конкретные физические карты, `weight: Int` — положительные относительные единицы 1…1000. Например A♦K♣, вес 1; 9♠9♥, вес 3. Это две точные комбинации. Веса нормируются на сумму: 1/4 и 3/4. Карточные ID используют прежнее соответствие `suit*13 + rank-2`. Число 0 представляется отсутствием комбинации в списке; дробные веса можно представить общими целыми единицами в пределах лимита.

Вес — предположение о вероятности руки **при уже известных Hero и доске**. Вес одного класса вроде AKs или QQ требует отдельного раскрытия всех физических комбинаций; текущий вход принимает конкретные пары карт. Префлоп-чарты и эмпирические частоты в примерах не используются.

Отклоняются: пустой/слишком большой список, вес вне диапазона, карта вне 0…51, повтор карты в руке, пересечение каждой руки с Hero/board, дубликат физической пары (включая обратный порядок), неверный размер Hero/board. Совпадающая карта в разных альтернативных руках допустима: в каждой ветви соперник имеет только одну из них. Несовместимая комбинация вызывает ошибку всего входа; автоматическое удаление и перенормировка отсутствуют. Текущий UI показывает валидированные фиксированные задания, редактор произвольного диапазона отложен.

## Расчёт

Для каждой руки i выполнить прежний точный `KnownHandEquityQuestion.calculate` с прежним evaluator. Из колоды этой ветви убрать Hero, board и **только выбранную** руку соперника. Карты остальных альтернатив остаются в колоде этой ветви. На флопе остаётся 45 карт, C(45,2)=990 продолжений; на тёрне — 44 продолжения. Результат ветви: Wᵢ,Tᵢ,Lᵢ,N. Во всех допустимых ветвях N одинаково.

pᵢ=wᵢ/Σw; equityᵢ=(Wᵢ+Tᵢ/2)/N; итог=Σpᵢ×equityᵢ.

Для точной арифметики счётчиков: Ww=ΣwᵢWᵢ, Tw=ΣwᵢTᵢ, Lw=ΣwᵢLᵢ; equity=(2Ww+Tw)/(2NΣw). Целые полубанки сохраняют точную рациональную долю до преобразования в Double для ответа/экрана. Максимум 8×1000×990=7 920 000 взвешенных единиц; удвоенный числитель ограничен 15 840 000. Ограничения входа сохраняют безопасную арифметику.

**Рассмотренные исходы** = сумма N по реальным комбинациям (2×990=1980 либо 2×44=88). **Взвешенные единицы** = N×Σw (3960 либо 176 в примерах). Это разные величины, подписи интерфейса раскрывают обе. Монте-Карло не применяется: seed, число испытаний симуляции и статистический интервал для этого метода неприменимы. Десятичные проценты на экране округляются.

## Три задания v1

1. Hero A♠A♥, flop 2♠7♥9♦. Opponent K♠K♥ с весом 3, Q♠Q♥ с весом 1. Проверяется точное взвешенное среднее двух ветвей.
2. Hero A♠K♥, turn T♠J♥Q♦2♣. Opponent A♦K♣ вес 1 (44 ничьи), 9♠9♥ вес 3 (44 победы Hero). Equity=0,25×0,5+0,75×1=87,5 %.
3. Те же карты, веса 3 и 1. Equity=0,75×0,5+0,25×1=62,5 %. Изменение предположения даёт разницу 25 процентных пунктов при тех же Hero/board.

Пользователь вводит процент 0…100 с точкой/запятой. Пустые, нечисловые и бесконечные значения блокируют проверку. Допуск ±0,5 п.п. относится к оценке ответа ученика. После ответа показываются все ветви с весами, W/T/L, equity, реальное число исходов, взвешенная формула и оговорка об условном диапазоне. Продолжение доступно после успешной локальной записи. Расчёт выполняется в отдельном actor, отмена проверяется между ветвями и внутри базового перебора.

## Прогресс и границы

Тема `rangeEquity`; versioned ID `equity-range-*-v1`. Числовые `PracticeAttempt` сохраняются прежним schema 2 JSON: UUID, дата, ID задания, ответ, точный числовой ключ и isCorrect. Фиксированные версии карточек связывают ID с картами и весами; отдельный произвольный снимок диапазона не сохраняется. Общая история сохраняет прежние темы. Same-ID retry, ошибка записи и блокировка после failed reload наследуют прежний store; экран сохраняет разбор при ошибке записи.

Общий банк с двумя участниками, завершённые ставки, равномерные неизвестные карты внутри ветви, без рейка и side pots. Позиции и стеки не влияют на эту условную equity вскрытия; стратегическая рекомендация о ставке требует дополнительных данных. Диапазон и веса придуманы как прозрачные математические условия, их пригодность для реального соперника не заявляется. Результат описывает среднюю долю банка; отдельный исход случаен. Редактор произвольных диапазонов, weighted hand classes, matrix, range narrowing, posterior updates, multiway и будущие расходы требуют следующей модели.
